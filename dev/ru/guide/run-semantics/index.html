    Семантика запуска¶

    AsyncETLPipeline.run даёт перечисленные ниже гарантии. Каждая пронумерована, и для каждой есть тест в tests/semantics/test_run_rules.py, имя которого начинается с номера правила, например test_r1_cursor_waits_for_settled_page. Изменение правила — это ломающее изменение: оно меняет тест правила и получает запись в MIGRATION.md.

    Запись считается завершённой (settled), когда она обработана, помечена как нерелевантная или пропущена как находящаяся в карантине. Запись считается надёжно сохранённой (durable), когда экспортёр надёжно хранит её сущности (R20). Страница считается застрявшей (stalled), когда записи на ней не удались и ни одна не была обработана или когда для неё не удался flush экспортёра. Страница завершает выдачу, когда у неё нет следующего курсора, нет элементов или она усечена (truncated).

    Выдачи с лимитом¶

    PubMed отдаёт первые 9 999 результатов запроса, а поиск по релевантности Semantic Scholar — первые 1 000. Их экстракторы помечают страницу, достигшую лимита, как усечённую, и действует R15: запуск завершается, а следующий запуск снова листает доступные результаты. Обработанные записи пропускаются по идентификатору, поэтому повторное сканирование стоит запросов выдачи, а не вызовов LLM: при page_size=100 до 10 запросов для Semantic Scholar и 100 для PubMed. Повторное сканирование также находит записи, попавшие в доступное окно после прошлого запуска, что важно для выдачи, отсортированной по релевантности. Чтобы избежать повторного сканирования, сузьте запрос, например диапазоном дат. У OpenAlex лимита нет: AsyncOpenAlexExtractor листает с помощью курсоров OpenAlex.
