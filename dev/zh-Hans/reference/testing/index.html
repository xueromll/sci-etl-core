    测试¶

    本页中的所有名称都可以从 sci_etl_core.testing 导入，它需要 testing extra。

    sci_etl_core.testing.extractors ¶

    The contract suite for extractors.

    Subclass :class:ExtractorContract in a test module under a name pytest collects, such as TestMyExtractor, and give it a make_extractor fixture. Serve the listing from a stub, such as an httpx.MockTransport, so the suite runs offline:

    import httpx
import pytest

from sci_etl_core.testing import ExtractorContract

from my_package import MyExtractor
from my_tests.stubs import serve_listing


class TestMyExtractor(ExtractorContract):
    @pytest.fixture
    def make_extractor(self):
        return lambda: MyExtractor(httpx.AsyncClient(transport=httpx.MockTransport(serve_listing)))

    The tests are plain functions that run each scenario with :func:asyncio.run, so pytest-asyncio is not needed.

    ExtractorContract ¶

    Tests every :class:~sci_etl_core.extractors.async_base.AsyncExtractor must pass.

    A subclass provides the make_extractor fixture. It returns a callable that takes no argument and returns a new extractor over the same listing each time it is called, as each run of a pipeline would build it. The suite calls it inside a running event loop. The listing must be offline, must answer the same request the same way every time, must hold at least two pages of :attr:page_size entries for :attr:query, and must end within :attr:max_pages pages.

    A subclass may also override the make_unavailable_extractor fixture to check that an unreachable source raises :class:~sci_etl_core.exceptions.UpstreamError rather than returning an empty page.

    Some tests check an optional capability and skip when the implementation lacks it: the offset test, when the extractor is not an :class:~sci_etl_core.extractors.async_base.OffsetListing, and the unavailable-source test, when make_unavailable_extractor returns None.

    query class-attribute ¶

    query: str = 'contract'

    The query every test lists.

    page_size class-attribute ¶

    page_size: int = 2

    The page size every test asks for.

    max_pages class-attribute ¶

    max_pages: int = 50

    The most pages the listing may take to end.

    make_unavailable_extractor ¶

    make_unavailable_extractor() -> (
    Callable[[], AsyncExtractor] | None
)

    Return a callable that builds an extractor whose source fails every request, or None.

    The source answers every request with a server-side failure, such as status 503, and the extractor must not wait between retries. The default returns None, which skips the unavailable-source test.

    sci_etl_core.testing.state ¶

    The contract suite for state managers.

    Subclass :class:StateManagerContract in a test module under a name pytest collects, such as TestMyStateManager, and give it a make_state_manager fixture:

    import pytest

from sci_etl_core.testing import StateManagerContract

from my_package import MyStateManager


class TestMyStateManager(StateManagerContract):
    @pytest.fixture
    def make_state_manager(self, tmp_path):
        return lambda: MyStateManager(tmp_path / "state.db")

    The tests are plain functions that run each scenario with :func:asyncio.run, so pytest-asyncio is not needed.

    StateManagerContract ¶

    Tests every :class:~sci_etl_core.state.async_base.AsyncStateManager must pass.

    A subclass provides the make_state_manager fixture. It returns a callable that takes no argument and returns a new state manager over the same storage each time it is called, as each run of a pipeline opens it, and the storage starts empty in every test. The suite calls it inside a running event loop, and ends each instance as a run ends: it awaits flush(), then aclose() when the instance has one. A state manager that keeps its state in memory returns the same instance on every call.

    A subclass may also override the write_newer_schema fixture to check that state from a newer release is refused.

    Some tests check an optional capability and skip when the implementation lacks it: failed attempts, when record_failure keeps the default that tracks nothing; forget, when the state manager is not :class:~sci_etl_core.state.async_base.Forgetting; reuse after aclose(), when it has no aclose; and the schema-version test, when write_newer_schema returns None.

    write_newer_schema ¶

    write_newer_schema() -> Callable[[], None] | None

    Return a callable that writes state from a newer schema version into the storage, or None.

    The suite calls it before it creates a state manager. The default returns None, which skips the schema-version test; override it when the implementation records a schema version.

    sci_etl_core.testing.exporters ¶

    The contract suite for exporters.

    Subclass :class:ExporterContract in a test module under a name pytest collects, such as TestMyExporter, and give it a make_exporter fixture and a read_exported fixture:

    import json

import pytest

from sci_etl_core.testing import ExporterContract

from my_package import MyExporter


class TestMyExporter(ExporterContract):
    @pytest.fixture
    def make_exporter(self, tmp_path):
        return lambda: MyExporter(tmp_path / "out.json")

    @pytest.fixture
    def read_exported(self, tmp_path):
        async def read(record_id):
            exported = json.loads((tmp_path / "out.json").read_text(encoding="utf-8"))
            return exported.get(record_id, [])

        return read

    The tests are plain functions that run each scenario with :func:asyncio.run, so pytest-asyncio is not needed.

    ExporterContract ¶

    Tests every :class:~sci_etl_core.exporters.async_base.AsyncExporter must pass.

    A subclass provides two fixtures:

    • make_exporter returns a callable that takes no argument and returns a new exporter over the same destination each time it is called, as each run of a pipeline would build it. The destination starts empty in every test, and the suite calls the callable inside a running event loop.
    • read_exported returns an async callable that takes a record id and returns the entities the destination holds for that record, in a form that compares equal when the content is the same, and an empty sequence when it holds none. The suite awaits it after the exporter has closed, and before, for an exporter with durable_writes = True.

    A subclass may also override the make_entities fixture when the exporter takes entities other than dicts, and the write_newer_schema fixture to check that a destination from a newer release is refused.

    Each run follows the pipeline's lifecycle: open(), write() for each record, flush(), then aclose(). Some tests check an optional capability and skip when the implementation lacks it: reading a write before flush(), when durable_writes is False, and the schema-version test, when write_newer_schema returns None.

    make_entities ¶

    make_entities() -> Callable[
    [RawRecord, int], Sequence[Any]
]

    Return a callable that builds count distinct entities for record.

    The default builds dicts with a name and a value key.

    write_newer_schema ¶

    write_newer_schema() -> Callable[[], None] | None

    Return a callable that writes a destination from a newer schema version, or None.

    The suite calls it before it creates an exporter. The default returns None, which skips the schema-version test; override it when the destination records a schema version.

    import pytest

from sci_etl_core.testing import EmbeddingStoreContract

from my_package import MyEmbeddingStore

    EmbeddingStoreContract ¶

    Tests every :class:~sci_etl_core.embeddings.store_base.AsyncEmbeddingStore must pass.

    A subclass provides the make_store fixture. It returns a callable that takes no argument and returns a new store over the same storage each time it is called, and the storage starts empty in every test. The suite calls it inside a running event loop and awaits aclose() on each store it creates. A store that keeps its chunks in memory returns the same instance on every call.

    A subclass may also override the write_newer_schema fixture to check that storage from a newer release is refused.

    Vectors have three dimensions, and scores are compared to within 1e-5, so a store may keep float32 vectors. Some tests check an optional capability and skip when the implementation lacks it: iter_records, when the store keeps the default that raises NotImplementedError, and the schema-version test, when write_newer_schema returns None.
