# Contributing to sci-etl-core

Thanks for your interest in improving `sci-etl-core`! New extractors, parsers,
exporters, and documentation fixes are all genuinely welcome — first-time
contributors included. This guide gets you productive quickly.

By participating you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).

## Development Setup

```bash
git clone https://github.com/<org>/sci-etl-core.git
cd sci-etl-core

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -e ".[async,llm,sql,viz]"
pip install pytest pytest-asyncio pytest-mock hypothesis
```

Python 3.10+ is required (the codebase uses `X | Y` unions and `slots=True`
dataclasses).

## The Async/Sync Model — Read This First

The **async modules are the single source of truth**. The synchronous classes
(`ArxivExtractor`, `CsvUpsertExporter`, `ETLPipeline`, …) are **generated** from
their async counterparts and carry a `# Generated by tools/generate_sync.py.
Do not edit.` banner.

- Edit the `*_async.py` file, never the generated sync file.
- Regenerate the facade after changing async source:

  ```bash
  python tools/generate_sync.py
  ```

- Commit both the async source and the regenerated sync output together.

## Running Tests

The suite is offline-first — no network or live LLM required.

```bash
pytest                       # everything
pytest tests/async           # async layer only
pytest --cov=sci_etl_core    # coverage report
```

**Coverage is expected to stay at 100%.** When you add code, add the tests that
cover it. Match the test layer to the implementation layer: async code gets
async tests (`@pytest.mark.asyncio`, `AsyncMock`); the generated sync facade gets
synchronous tests. New public ABCs should be exercised by the conformance tests
in `tests/contract/`.

## Code Style

- **PEP 8** naming: `snake_case` functions and variables, `CapWords` classes,
  `UPPER_CASE` constants.
- **Type hints on every public signature.** The package ships `py.typed`;
  keep it accurate.
- **Small, single-responsibility functions.** Prefer composition and dependency
  injection over branching on hard-coded logic.
- **Minimal comments.** Let names carry meaning; reserve comments and docstrings
  for intent that code can't express.
- **American English** for identifiers and docstrings.
- **No domain-specific constants** in the core — keep it field-agnostic.

Recommended tooling (run before pushing):

```bash
ruff check .        # lint
ruff format .       # format
mypy src/sci_etl_core
```

## Commit Format

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <short summary>
```

Common types: `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `chore`.

Examples:

```
feat(extractors): add PubMed async extractor
fix(exporters): serialize concurrent CSV upserts
docs(readme): clarify event-loop caveat for sync facade
```

Keep the summary imperative and under ~72 characters. Reference issues in the
body (`Closes #123`).

## Pull Request Process

1. **Open an issue first** for anything non-trivial so we can agree on the
   approach.
2. **Branch** from `main`: `feat/pubmed-extractor`.
3. **Write tests** alongside your change; keep coverage at 100%.
4. **Regenerate the sync facade** if you touched async source.
5. **Run** the lint / type / test commands above locally.
6. **Fill in** the [pull request template](.github/PULL_REQUEST_TEMPLATE.md).
7. **Keep PRs focused** — one logical change per PR is easiest to review.

A maintainer will review promptly. Expect a friendly, constructive exchange;
requested changes are about the code, never about you.

## Adding a New Component

Most contributions plug into an existing abstract base class:

- **Extractor** → subclass `AsyncExtractor`, implement `search`,
  `parse_listing`, `fetch_full_text`, then regenerate the sync facade.
- **Parser** → subclass `Parser`, implement `extract_text`.
- **Exporter** → subclass `AsyncExporter`, implement `export`.
- **Processor** → subclass `Processor`, implement `process`.

Wire the new class into the relevant package `__init__.py` and add it to
`__all__` so it's part of the public API.

Happy hacking — and thank you for contributing!
