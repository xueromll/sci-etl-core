# sci-etl-core

`sci-etl-core` — библиотека Python для превращения научных статей из любой
области науки в структурированные данные с возможностью поиска. Она получает
статьи из arXiv, PubMed, OpenAlex и Semantic Scholar, читает их полный текст,
извлекает с помощью LLM нужные вам значения и обеспечивает поиск по статьям на
вашем собственном компьютере.

Результат показывает udg-catalogue. Он отбирает статьи по астрофизике в arXiv,
извлекает измерения ультрадиффузных галактик и публикует сопоставленный
каталог из 1 927 объектов с поиском по ключевым словам и по смыслу среди
статей, на которых он основан. `sci-etl-core` обеспечивает получение, разбор,
извлечение, кэширование, возобновляемое состояние и поиск, а udg-catalogue
добавляет астрономию: промпты, правила валидации, сопоставление по положению на
небе и панель мониторинга.

Ничто в библиотеке не привязано к астрономии. Знания предметной области
находятся в ваших промптах, валидаторах и нормализаторах, поэтому те же
строительные блоки работают для любой области науки.

## Возможности {#features}

- **Подключаемые асинхронные интерфейсы** для каждого этапа: `AsyncExtractor`,
  `Parser`, `AsyncLLMClient`, `AsyncRelevanceFilter`, `AsyncEntityExtractor`,
  `AsyncExporter`, `AsyncStateManager`, а также `AsyncEmbedder`, `TextChunker`
  и `AsyncEmbeddingStore` для семантической памяти. Запускайте весь конвейер
  или используйте только нужные части, например поиск.
- **Асинхронная оркестрация в первую очередь** — каждый компонент является
  `async`-реализацией. `AsyncETLPipeline` обрабатывает записи с ограниченным
  параллелизмом, а `ETLPipeline` запускает тот же конвейер из блокирующего
  кода.
- **Явная сигнализация об ошибках** — сбой транспорта или некорректная выдача
  прерывает запуск с `PipelineAborted` (с частичным счётчиком), а не выглядит
  как конец данных. Одна неудавшаяся запись записывается в журнал и остаётся
  до следующего запуска, а записи, которые продолжают проваливаться, пока
  ничего не обрабатывается, останавливают запуск, вместо того чтобы впустую
  перебирать остаток выдачи.
- **Возобновляемое состояние, устойчивое к сбоям** — бэкенды на обычных файлах
  или SQLite хранят идентификаторы обработанных записей, курсор выдачи и
  неудачные попытки, так что запись, которая продолжает проваливаться,
  помещается в карантин; запись CSV и метаданных использует атомарные
  переименования. Выдачи «сначала новые» подхватывают новые статьи без
  повторного сканирования.
- **Корректное завершение** — Ctrl+C или SIGTERM дают завершиться записям в
  обработке, сбрасывают состояние на диск и выбрасывают `PipelineInterrupted`.
- **Вежливые повторы и ограничения частоты** — каждый встроенный экстрактор и
  OpenAI-совместимые клиенты чата и эмбеддингов ждут столько, сколько просит
  заголовок `Retry-After` ответа с ограничением частоты, вплоть до
  настраиваемого предела, и принимают ограничители частоты, которые можно
  делить между компонентами и задавать для отдельных хостов.
- **События прогресса, метрики и расход токенов** — типизированные события по
  каждой записи, метрики запуска со счётчиками, длительностями и сбоями, а
  также токены, израсходованные каждым запуском.
- **Типизированное извлечение и утверждения** — опишите сущность моделью
  Pydantic, чтобы получать проверенные типизированные сущности и причины каждого
  отклонения, или извлекайте утверждения, которые хранят статью,
  предложение-доказательство и модель для каждого значения.
- **Кэширование ответов LLM** — кэш в памяти или в SQLite отвечает на
  повторяющиеся промпты без нового вызова API.
- **Семантическая память (необязательно)** — разбивайте полные тексты на
  фрагменты и сохраняйте их эмбеддинги в векторное хранилище в памяти или в
  SQLite, ищите похожие статьи или определяйте релевантность по сходству
  эмбеддингов вместо вызова LLM.
- **Локальный поиск и обзор** — булевы запросы по текстовому индексу SQLite
  FTS5, которому нужна только стандартная библиотека, гибридный поиск,
  объединяющий BM25 со сходством эмбеддингов, фасеты метаданных и графы
  связанных статей.
- **Внедрение зависимостей повсюду** — HTTP-клиенты, парсеры, модели, промпты,
  схемы и пути вывода передаются аргументами конструктора.
- **Готовые реализации в комплекте** — экстракторы arXiv, PubMed, Semantic
  Scholar и OpenAlex; OpenAI-совместимые клиенты чата и эмбеддингов; локальный
  эмбеддер sentence-transformers; парсеры PDF / LaTeX / HTML / DOCX / JATS XML;
  экспортёры CSV и JSON Lines; приёмники в таблицы SQL и в 3D-графики Plotly;
  процессоры датафреймов и валидаторы записей.
- **Типизированная конфигурация** из YAML и переменных окружения с валидацией
  Pydantic и ключами API в `SecretStr`.
- **Офлайн-набор тестов** — pytest с моками, тесты свойств Hypothesis и тесты
  соответствия ABC.
- **Типизация по PEP 561** (`py.typed`) для проверки типов в зависимом коде.
