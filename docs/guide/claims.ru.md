# Утверждения и происхождение

Утверждение — это одно значение или высказывание, извлечённое из статьи и
сохранённое вместе со статьёй, из которой оно взято, предложением, из которого
оно прочитано, а также моделью, промптом и схемой, которые его получили.
Утверждения позволяют таблице для каждого значения ответить на вопрос «какая
статья это говорит?», хранить противоречащие данные рядом и находить все
значения, которые нужно переизвлечь после исправления промпта.

!!! note "Предварительный API"
    `sci_etl_core.claims` появился в 0.6.0 и имеет статус предварительного:
    имя может измениться в минорном релизе, с записью в CHANGELOG, пока от
    него не зависит ни один известный потребитель.

## Извлечение утверждений {#extracting-claims}

`AsyncLLMClaimExtractor` запрашивает у модели объекты `ClaimDraft`, проверяет
их, находит цитату каждого черновика в тексте, отправленном модели, и
возвращает объекты `Claim`. `AsyncClaimStoreExporter` сохраняет их запись за
записью:

```python
import os

from sci_etl_core import AsyncETLPipeline, AsyncOpenAICompatibleClient
from sci_etl_core.claims import (
    AsyncClaimStoreExporter,
    AsyncLLMClaimExtractor,
    AsyncSqliteClaimStore,
    AsyncSqliteRejectionStore,
)

CLAIM_PROMPT = (
    "List every measurement of an ultra-diffuse galaxy in the paper. Reply with JSON: "
    '{"claims": [{"kind": "measurement", "subject": "...", "predicate": "effective_radius", '
    '"quantity": {"verbatim": "2.9 kpc", "value": 2.9, "unit_text": "kpc"}, '
    '"context": {"band": "g"}, "quote": "the sentence, copied exactly"}]}.'
)

llm = AsyncOpenAICompatibleClient(
    api_key=os.environ["LLM_API_KEY"], base_url="https://api.openai.com/v1", model="gpt-4o-mini"
)
claims = AsyncSqliteClaimStore("data/claims.db")
rejections = AsyncSqliteRejectionStore("data/rejections.db")

pipeline = AsyncETLPipeline(
    extractor=extractor,
    relevance_filter=relevance_filter,
    entity_extractor=AsyncLLMClaimExtractor(llm, CLAIM_PROMPT, rejections=rejections),
    exporter=AsyncClaimStoreExporter(claims),
    state_manager=state_manager,
    closeables=[llm, claims, rejections],
)
```

Унаследуйте `ClaimDraft`, чтобы сузить `predicate` или ключи `context` для
своей области, и передайте подкласс как `schema=`. Модель никогда не
предоставляет идентификаторы, смещения или сведения о происхождении — их
вычисляет код.

## Что содержит утверждение {#what-a-claim-holds}

| Поле | Значение |
|------|----------|
| `claim_id` | дайджест записи, вида, субъекта, предиката, объекта, полярности, контекста, дословного текста величины, фрагмента и хэша схемы |
| `kind` | `"measurement"`, которому нужна `quantity`, или `"assertion"`, которому нужен `object` |
| `subject`, `predicate`, `object` | то, о чём утверждение, так, как это называет статья |
| `quantity` | число так, как его записывает статья: `verbatim`, `value`, `unit_text`, `qualifier`, `uncertainty` |
| `statistics` | размеры эффекта, доверительные границы, *p*, тестовые статистики, размеры групп, каждое необязательно |
| `context` | условия, например полоса или выборка, в виде отсортированных пар ключ–значение |
| `span` | `record_id`, начальное и конечное смещения предложения или предложений, в которых найдена цитата, и сама цитата |
| `stamp` | модель, хэш промпта, хэш схемы и релиз библиотеки |

Модель, промпт и релиз библиотеки намеренно не входят в `claim_id`: повторное
извлечение статьи другой моделью даёт те же идентификаторы везде, где поля
совпадают, с новым штампом. Субъекты сравниваются точно, поэтому `"DF44"` и
`"DF 44"` — разные утверждения; сопоставление имён — более поздний шаг, который
никогда не переписывает утверждения. `Claim.to_row()` даёт одно плоское
отображение — ту форму, которую пишут хранилища и экспортёры CSV и JSON Lines.

## Привязка к тексту {#grounding}

`locate_quote(text, quote)` находит цитату в тексте, отправленном модели, —
точно после схлопывания пробелов или, иначе, нечётко с помощью `difflib` при
`min_ratio` (0,9) или выше — и расширяет совпадение до целых предложений.
Разделитель предложений знаком с научной прозой: `et al.`, `Fig. 3`,
`Eq. (2)`, `i.e.`, `R.A.` и десятичные числа не заканчивают предложение.
Черновик, цитата которого не найдена, считается непривязанным: он
записывается в журнал, помещается в хранилище отклонений с кодом
`"ungrounded"` и не возвращается.

## Хранилища {#stores}

`InMemoryClaimStore` и `AsyncSqliteClaimStore` следуют одному контракту:

- `replace_record(record_id, claims)` заменяет утверждения записи в одной
  транзакции и возвращает новую ревизию. Пустой список очищает запись — именно
  это происходит, когда повторное извлечение ничего не находит, потому что
  пайплайн записывает каждую обработанную запись.
- `claims_for_records(record_ids)` читает утверждения обратно, в сохранённом
  порядке.
- `changes_since(revision)` постранично выдаёт изменения по ревизии, которая
  только растёт, так что последующее задание может продолжить с того места,
  где остановилось.

Хранилище SQLite индексирует утверждения по записи, по
`(subject, predicate, object)`, по паре контекста и по каноническому виду и
значению, а также записывает версию своей схемы, поэтому более поздняя
sci-etl-core открывает файлы, записанные 0.6.0.

Сбой хранилища в `AsyncClaimStoreExporter.write` приводит к неудаче записи,
которая повторяется при следующем запуске и засчитывает одну попытку, как
любая неудавшаяся запись. Это не сбой компонента памяти.
