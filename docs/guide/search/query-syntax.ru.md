# Синтаксис запросов

| Конструкция | Пример | Находит |
|-------------|--------|---------|
| Термин | `galaxy` | слово без учёта регистра и диакритики, так что `Müller` находит `Muller` |
| Фраза | `"dwarf galaxy"` | слова рядом друг с другом, по порядку |
| Префикс | `photometr*` | любое слово, начинающееся с `photometr` |
| Ограничение по полю | `title:quasar`, `title,abstract:"dwarf galaxy"` | только в названных полях: `title`, `abstract`, `body` |
| Близость | `NEAR(dwarf "dark matter" halo*, 5)`, `title:NEAR(dwarf halo)` | все термины и фразы в одном поле, не дальше 5 токенов друг от друга (по умолчанию 10), в любом порядке |
| И | `a AND b`, `a && b`, `a b` | оба |
| Или | `a OR b`, `a \|\| b` | любой из двух |
| Не | `NOT a`, `-a` | документы без `a` |
| Группировка | `(a OR b) -c` | |

`NOT` связывает сильнее всего, затем `AND`, затем `OR`. Операторы пишутся
заглавными буквами, поэтому `and` — обычное слово. Слово, которое
токенизатор разбивает на части, например `H-alpha`, ищется как фраза из этих
частей.

## Близость {#proximity}

`NEAR(...)` принимает термины, фразы и префиксные термины через пробел, а затем
необязательно запятую и целое число токенов. Если выбрать вхождения так, чтобы
то, которое начинается последним, начиналось с токена `p`, каждый другой
операнд должен заканчиваться не более чем за столько токенов до `p`:
`NEAR(a b, 2)` находит `a x x b` и `b x a`, но не `a x x x b`.

- **Ограничивайте группу, а не её части.** `abstract:NEAR(dwarf halo)` ищет в
  аннотации; ограничение по полю внутри скобок, например
  `NEAR(title:dwarf halo)`, — это `SearchQueryError`.
- **Внутри только слова.** `AND`, `OR`, `NOT`, `-`, `&&`, `||` и вложенные
  скобки внутри группы отвергаются. Вместо этого отрицайте или комбинируйте
  группу целиком, как в `quasar -NEAR(dwarf halo, 3)`.
- **Краткие формы.** Группа с одним операндом, например `NEAR(dwarf)`, — это
  просто этот термин. Группа из одной фразы в кавычках, например
  `NEAR("dwarf halo", 3)`, ищет слова фразы рядом друг с другом, а не саму
  фразу.
- **Заглавными буквами и без пробела.** `NEAR` должен быть написан заглавными
  буквами, и сразу за ним должна идти `(`; `near(a b)` и `NEAR (a b)`
  читаются как слово `near` и термины `a` и `b`.

Группа `NEAR` ранжирует, фильтрует и подсвечивает, как любой другой термин, в
обоих текстовых хранилищах. В гибридном поиске её слова превращаются в
эмбеддинг, как и остальной запрос, кроме её префиксных терминов. `describe`
возвращает группу как один `QueryChip`, у которого `near` — её расстояние.

Одно исключение касается `AsyncSqliteFts5Store`: некоторые сборки SQLite,
включая 3.50.4, для части документов не могут подсветить группу с
ограничением по полю внутри `OR` или `NOT`, например
`dwarf OR title:NEAR(dwarf halo)` или `dwarf -title:NEAR(dwarf halo)`. Тогда
поиск вызывает `SearchQueryError` с указанием версии SQLite. Уберите
ограничение по полю из группы или ищите каждую альтернативу `OR` отдельно.
`filter_ids` и хранилище в памяти это не затрагивает.

## Разбор {#parsing}

Разбор — чистая синхронная операция, поэтому строка запроса может выполнять
его при каждом нажатии клавиши. Некорректный запрос вызывает
`SearchQueryError`, у которого `position` и `token` указывают на ошибку, а
`describe` возвращает разобранные слова и фразы в виде `QueryChip` для
отображения:

```python
from sci_etl_core import SearchQueryError
from sci_etl_core.search import describe, parse_query

try:
    chips = describe(parse_query("title:quasar (blazar OR -dwarf"))
except SearchQueryError as exc:
    print(f"{exc} (column {exc.position}: {exc.token!r})")
```
