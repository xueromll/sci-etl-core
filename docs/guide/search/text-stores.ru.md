# Текстовые хранилища

- **`InMemoryTextSearchStore(facet_keys=...)`** подходит для тестов и
  кратковременных запусков. Он находит ровно те же записи, что и хранилище
  SQLite, и оценивает их по той же формуле BM25.
- **`AsyncSqliteFts5Store(path, facet_keys=..., weights=...)`** сохраняет
  индекс на диске. Текст каждой статьи хранится один раз, каждая запись — одна
  транзакция, а любой сбой SQLite, включая файл, который не является базой
  данных, вызывает `SearchStoreError`.
  `weights=BM25Weights(title=10.0, abstract=4.0, body=1.0)` задаёт, сколько
  весит совпадение в каждом поле; это значения по умолчанию.
- **Нужен FTS5.** Хранилищу нужен Python, чей SQLite собран с FTS5; иначе при
  создании оно вызывает `SearchStoreError`. `fts5_available()` проверяет это
  заранее; `InMemoryTextSearchStore` работает везде.
- **Обслуживание выполняется явно.** `optimize()` объединяет сегменты индекса.
  `integrity_check()` возвращает `False`, когда индекс расходится с сохранёнными
  документами, например после того, как файл редактировали другие инструменты,
  а `rebuild_index()` восстанавливает его из сохранённого текста, ничего не
  загружая. Файл, созданный более новой версией библиотеки, вызывает
  `SearchStoreError` вместо того, чтобы использоваться.
- **Собственные хранилища** наследуют `AsyncTextSearchStore`; см.
  [Добавление нового компонента](../../project/contributing.md#adding-a-new-component).
