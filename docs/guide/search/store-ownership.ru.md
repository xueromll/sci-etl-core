# Владение хранилищами

Три факта делают важным вопрос о том, кто закрывает хранилище:

- `aclose()` у хранилища SQLite не окончателен: последующий вызов снова
  открывает соединение.
- `async with pipeline` закрывает каждый элемент `closeables` при каждом
  выходе из блока.
- Блокировка хранилища принадлежит первому циклу событий, который за неё
  конкурирует. Использование того же экземпляра из второго цикла завершается
  ошибкой, но только когда оба используют его одновременно, поэтому тихий тест
  проходит, а нагруженный интерфейс ломается.

Поэтому у каждого экземпляра хранилища должен быть ровно **один владелец** —
область, которая переживает всех его пользователей, и только владелец вызывает
`aclose()`. Используйте каждый экземпляр из **одного цикла событий**. Все
остальные только заимствуют: `AsyncHybridSearcher`, источники рёбер и
`AsyncCompositeIngestor` никогда не закрывают хранилище.

| Развёртывание | Владелец хранилищ SQLite | `closeables` пайплайна |
|---------------|--------------------------|------------------------|
| Пайплайн и интерфейс в отдельных процессах | каждый процесс — для экземпляров, которые он открыл на общих файлах | перечисляет собственные экземпляры пайплайна |
| Одноразовый скрипт, который загружает и выполняет запросы внутри `async with pipeline` | пайплайн | перечисляет хранилища; запросы выполняются внутри блока |
| Долгоживущее приложение на одном цикле событий, запускающее загрузки | приложение, которое закрывает их при завершении | **не** должен их перечислять, иначе конец каждого запуска закроет их, а следующий запрос снова откроет соединение без владельца |
| Блокирующий `ETLPipeline` плюс приложение на собственном цикле | два набора экземпляров на одних и тех же файлах: один использует фоновый цикл пайплайна, другой — цикл приложения | перечисляет набор пайплайна |

Режим WAL в SQLite позволяет одному процессу читать, пока другой пишет.
