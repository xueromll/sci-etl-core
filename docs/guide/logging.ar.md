# التسجيل

تسجّل كل وحدة في sci-etl-core رسائلها عبر الوحدة القياسية `logging`، تحت مسجِّل
يحمل اسم الوحدة، مثل `sci_etl_core.pipeline_async` أو
`sci_etl_core.extractors.arxiv_async`. وتقع كلها تحت المسجِّل `sci_etl_core`.
لا تثبّت المكتبة أي معالجات ولا تضبط أي مستويات، فلا يُطبع شيء حتى يضبط التطبيق
التسجيل:

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
    handlers=[logging.FileHandler("pipeline.log", encoding="utf-8"), logging.StreamHandler()],
)
logging.getLogger("sci_etl_core.extractors").setLevel(logging.WARNING)
```

معاني المستويات:

| المستوى | يُستخدم لـ |
|---------|-----------|
| `ERROR` | عطل في مَصرِف أو مخزن يُبلغ عنه التشغيل: فشل `flush` أو `aclose` في مصدِّر، أو تعذّر حفظ الحالة، أو تعذّر إغلاق مورد، أو رفع معالج أحداث استثناءً |
| `WARNING` | ما يغيّر ناتج التشغيل أو كلفته: فشل سجل أو تخطّيه، أو وضع سجل في الحجر، أو توقف مصدر عند حد نتائجه أو رفضه مؤشرًا، أو فشل واجهة الذاكرة الخلفية، أو تنزيل غير قابل للاستخدام، أو إعادة محاولة، أو إشارة إيقاف |
| `INFO` | ملاحظات روتينية: رفض التحقق لكيان أو ادعاء، والموضع الذي استُؤنف منه تشغيل `newest_first` |

تحتفظ الرسائل بالصياغة التي كانت الإصدارات السابقة تمررها إلى الكائنات القابلة
للاستدعاء `logger=`، مثل `Record processing failed: LLMError('...')`، ولذلك يظل
أي مرشح أو تنبيه كُتب لها مطابقًا.

وتبقى أحداث التقدم الموضحة في [قابلية الملاحظة](observability.md) القناة
المنظَّمة: احسب السجلات والصفحات والنتائج من الأحداث، واستخدم السجلات النصية
لمعرفة الأسباب.
